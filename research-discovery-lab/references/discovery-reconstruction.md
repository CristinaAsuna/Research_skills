# 重建论文的发现过程

目标不是复述论文，而是回答四个问题：作者当时**看到了什么**，为什么觉得**奇怪**，**怎么想到**解释，又**怎么验证**。论文引言是事后整理的叙事，真实的发现史很少写进论文，所以重建是带证据等级的推断。

## 1. 证据来源（由强到弱）

1. **论文原文**
   - 引言里的动机句，以及 "we observe / surprisingly / interestingly / contrary to / we find that" 这类句子。
   - 第一张不是方法框图的图。
   - 论文里最简单的实验。
   - 消融里"去掉 X 之后具体怎么坏"。
   - 附录中的负结果。
2. **作者前作**：前一篇论文的局限、失败案例和附录里的副现象，常常就是下一篇的起点。查看作者近 2–3 年的论文列表。
3. **作者的公开叙述**：talk、博客、访谈、OpenReview 讨论与 rebuttal、代码仓库的早期提交。
4. **同期工作**：同一现象最早由谁、在什么设置下报告过。
5. **推断**：以上都没有时，基于领域常识给出合理路径，必须标为 `[推断]`。

在 DISCOVERY §0 记录实际读过的部分；只看了摘要或二手资料要写明。直接引用不超过 15 词，并注明出处。

## 2. 找关键观察的线索

- **动机句中的对比**："X 被认为是必要的，但……"、"尽管 X，仍然……"。
- **Figure 1/2 是现象图**：如果是曲线、散点或样本而不是框图，它通常就是关键观察。
- **最便宜的实验**：toy、合成数据、小模型的实验，往往是作者最早做的。
- **最反直觉的设计选择**：方法里这一处背后多半有一个观察。
- **标题的修辞**："Back to Basics"、"Rethinking…"、"…is all you need" 往往暗示被修正的共识。
- **作者前作**：前作的失败案例在新论文里被"解决"。

## 3. 发现原型

给每个 topic 选一个主原型，填在 EXPERIMENTS.md 的"发现原型"列和 DISCOVERY.md 末尾。积累多了，用户就能更快认出论文属于哪种发现模式。

| 原型 | 特征 | 重建时追问 |
| --- | --- | --- |
| 标准流程中的反常 | 常规训练或评估里出现不该出现的现象 | 在什么条件下出现？是 bug 还是机制？ |
| 跨领域迁移 | 把其他领域的工具或视角搬过来 | 那里的隐含假设为什么在这里也成立？ |
| 删掉"必要"组件 | 去掉公认必要的部件，结果仍然好甚至更好 | 原来的必要性来自哪个隐含假设？ |
| 推到极限 | 把某个量推到极端，暴露机制 | 在极限处什么先坏？ |
| 统一两个观察 | 两个看似无关的现象有共同原因 | 共同变量是什么？ |
| 诊断量变成方法 | 某个测量与性能相关，于是直接去优化它 | 这种相关是因果吗？ |
| 理论先行 | 先有推导，再找现象验证 | 推导依赖哪些假设，toy 能否违反它们？ |

## 4. 推理链（DISCOVERY §4）

链条的六个环节：

1. **观察**：作者看到的现象。
2. **疑问**：它与共识冲突在哪里。
3. **假设**：一句话的因果陈述。
4. **可检验预测**：如果假设成立，改变 X 就会看到 Y。
5. **论文中的实验**：作者实际用来检验的实验。
6. **方法**：由假设推出的方法。

每个环节都要标出证据来源和置信度：

- **证据**：`[原文 §x/Fig y]`、`[作者前作 …]`、`[talk/OpenReview …]`，或 `[推断]`。
- **置信度**：高 = 原文直接陈述；中 = 原文图表强烈暗示；低 = 推断。

不要把方法有效当成假设成立的证据，方法也可能因为别的原因有效。链条不能跳步：缺少"可检验预测"这一环，就无法设计 toy。

## 5. 备选路径与竞争解释

- **备选发现路径**：同一篇论文可能有别的发现顺序，例如先有方法后补观察、从工程失败出发、从理论出发。至少写一条，并说明为什么它的可能性较低。
- **竞争解释**：对关键观察列出至少 2 个其他可能的原因，例如数据、指标、优化、容量、实现细节、混杂变量。逐个标明论文用哪个实验排除了它。没被排除的，就是 E3 及之后 toy 的好候选。

## 6. 预测问题库（揭晓前提问，按 LEARNING 阶段）

| 阶段 | 问什么 |
| --- | --- |
| S1 跟随 | 只问结果："在 E1 中，<旋钮> 从 a 变到 b 时，<指标> 会上升、下降、不变还是先升后降？大约变到多少？" |
| S2 推测 | 加问："你觉得作者在反驳什么共识？""你猜作者最先看到的现象是什么？" |
| S3 设计 | 加问："如果让你设计一个 5 分钟能跑完的实验来看到这个现象，你会拧哪个旋钮、和什么比、画什么图？"用户先写，agent 再给 PLAN。 |
| S4 质疑 | 加问："除了作者的解释，还有什么可能导致这个现象？用什么实验区分？" |
| S5 原创 | topic 从用户的问题开始："你预期看到什么？什么结果会让你放弃这个想法？" |

提问原则：

- 问题必须能被实验结果判定对错。
- 可以给选项，但允许自由回答。
- 每次只问 2–3 个，不连环追问。
- 用户跳过就记"用户跳过"，不施压。
- 揭晓时把用户的猜测和重建并排写进 DISCOVERY §7，指出用户漏掉的那条具体线索。

## 7. 常见错误

- 把引言的叙事当成真实的发现史。
- 只重建"方法为什么好"，没有重建"作者为什么会想到"。
- 编造作者原话，或写"作者在某次 talk 中说"却没有出处。
- 推理链从观察直接跳到方法。
- 把竞争解释写成稻草人。
- 让 toy 复现论文的最终方法，而不是复现关键观察。
