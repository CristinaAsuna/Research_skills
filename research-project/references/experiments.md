# 实验：类型、准入和卡片

实验是为了改变一个决定。写不出"结果会改变什么"的实验不做。

## 1. 四种类型

| 类型 | 用途 | 约束 |
| --- | --- | --- |
| trunk | 让"数据→训练→推理→评测"端到端出一个可信的数 | 同一时间只有一个。完成后按 [trunk-migration](trunk-migration.md) 锁定 |
| ablation | 主干加一处改动 | 只改一个旋钮；用主干的评测入口和评测集 |
| analysis | 解释主干为什么这样表现 | 读主干已缓存的推理结果，不重新训练，不重新生成缓存 |
| spike | 试一个新方向，例如换一类模型 | 在 scratch/ 里做；卡片写明时间上限和停止门槛；到期必须收尾 |

主干还没有锁定时，只做 trunk 类型。此时做消融和分析，结果没有可比的对象。

## 2. 准入流程

1. 用户提出问题，或者 agent 从 STATE.md 的排队里取第一项。
2. `tools/project.py new <slug> --type <类型>` 生成卡片和登记行。
3. 填写卡片，交给用户批准。批准前不写实验代码。
4. 提交 `exp(<id>): card`。这次提交固定了预测，之后不再修改"预测"和"推翻条件"两节。
5. 把 STATE.md 的"当前唯一问题"指向这张卡片，登记表状态改为 running。
6. 执行：先用最小规模跑通，再正式运行。正式运行前代码必须已提交。
7. 写 `result.json`，在卡片的"结果"一节写结论，登记表填一句话结论。
8. 由用户或新会话核对数字后，状态改为 done（或 stopped），从 STATE.md 的排队里取下一项。
9. 收尾：`tools/project.py audit --exp <id>` 列出冗余 checkpoint 和放错位置的缓存，生成清单；交给用户确认后运行 `tools/project.py prune <清单> --yes`。

执行中出现以下情况就停下来问用户：超过预算的 1.5 倍；出现 NaN 或发散；发现会影响结论的 bug；卡片有歧义。

## 3. 卡片怎么写

卡片不超过 40 行。每一节一到三行。

- **问题**：一句话，能用一个数或一张图回答。
- **影响的决定**：结果 A 时下一步做什么，结果 B 时下一步做什么。
- **预测**：方向和大致幅度。用户和 agent 可以各写一条。
- **推翻条件**：看到什么结果就承认预测错了。
- **相对主干的改动**：只有一处。写配置文件名。
- **评测**：默认写"同 PIPELINE.md"。有任何不同都要写明，并说明为什么仍然可比。
- **计算和存储预算**：GPU 小时或墙钟时间；存储上限写成"存储上限 N GB"，`audit` 和 `check` 会对照 runs/<id>/ 的实际大小；达到什么数值或时间就停。
- **要保存的产物**：逐项写文件名。checkpoint 默认只有 best.pt；last.pt、best_<name>.pt 等其他文件不写进来，实验结束时会被 `audit` 列为冗余。
- **结果**：运行后填写。写数字、与主干的差、结论，以及这个实验不能说明什么。

### 示例

```markdown
# 2026-11-20-sd15-controlnet

类型：spike　状态：running

## 问题
SD1.5 ControlNet 在 val-117 上的 D-NMAE 能否低于主干 ResUNet-96 的 0.498？

## 影响的决定
- 低于 0.498：开一张 ablation 卡片，用 3 个 seed 确认，考虑取代主干。
- 不低于 0.498：停止预训练扩散模型这条线，回到主干的 sim2real 问题。

## 预测
- 用户：能到 0.45。
- agent：到不了 0.6，VAE 重建误差是下限。

## 推翻条件
3000 步时 D-NMAE 仍高于 0.8，agent 的预测成立，用户的预测被推翻。

## 相对主干的改动
configs/exp/2026-11-20-sd15-controlnet.yaml：模型换成 SD1.5 加 ControlNet，其余不变。

## 评测
同 PIPELINE.md。

## 计算和存储预算
24 GPU 小时；存储上限 10 GB。4000 步内没有低于 0.6 就停。

## 要保存的产物
result.json；figures/curve.png；checkpoints/best.pt。

## 结果
【运行后填写】
```

## 4. spike 怎么收尾

到达时间上限或停止门槛时，只有三种结局：

1. **值得继续**：新开一张 ablation 或 trunk 候选卡片，把用得上的代码从 scratch/ 整理进 src/，并补测试。
2. **不值得继续**：登记表状态改为 stopped，写一句带数字的结论；在 docs/PROJECT.md 的"已排除的方向"加一行。scratch/ 里的代码不进 git。
3. **没有结论**：只有在用户同意时才延长一次，并在卡片里写新的上限。

不允许的结局：到期后换一个相近的设置接着试，却不新开卡片。

## 6. 常见错误

- 提示写成"分析一下为什么效果差"。这没有停止条件，agent 会把想到的都做一遍。应当改成一个具体问题和它影响的决定。
- 一张卡片里改了两处。结果出来后无法归因。
- 每个实验各写一个评测脚本，或者换了评测集。数字之间不再可比。
- 为下一个阶段新建一个包，再去 import 上一个阶段的包。上游一改，后面的结果全部悄悄变化。
- 把同一个结果存成数组、图片、表格和网页四种格式。
- 训练代码自己调用 `torch.save` 存 `step_*`、`smoke.pt` 和好几种 best，没有人收尾，几个月后积累几十 G。应当只用 `artifacts.save_checkpoint`，实验结束跑 `audit`。
- 没有先 `source tools/env.sh`，matplotlib、CUDA 的缓存和 pip 装的包落进了实验目录。
- 做完不更新 STATE.md。下一个会话读到的是过期状态。

## 7. 审查用户自己设计的实验（Claude 只审，不代设计）

用户带着自己的实验或方法设计来时，Claude 提问、查可行性、把设计写成卡片，不替用户换方案；设计取舍留给用户。逐项检查，先给问题清单，用户确认后再改写成卡片：

1. **锚点**：复现论文时，锚点是论文报告的最早检查点和它的数值，不是更小的 toy；没有论文数值就用主干的数。写不出锚点，就没法判断结果对不对。
2. **先确认效应存在**：先在锚点设置下复现基线和论文的核心效应（至少达到论文幅度的一半），再做归因或消融。没达到就停下汇报，不往下做。
3. **缩小规模是否改掉了机制依赖的条件**：欠训练、数据不够、任务难度。缩小后基线若已贴近上限（几乎没有改善空间），实验就没有辨识力。
4. **阈值**：以实测噪声（seed 间波动、评估采样噪声）和剩余空间为单位，不用随手写的百分比。
5. **零结果要配阳性对照**：“去掉 X 也不掉点”这类主张，先证明这个实验能测出一个已知大小的下降。
6. **成本和止损**：每步 FLOPs × 步数 ÷ 实际吞吐，给出 GPU 小时和运行机器（按 lab-machines 路由）；设中间检查点，曲线偏离锚点就停。
7. **只改一处**，其余与基线相同。

例（SRA → Self-Flow）：论文只报告 SiT-B / ImageNet-256 在 100K、400K、800K 步的 FID，单时间步 62.95 / 32.10 / 26.34，双时间步 58.16 / 30.20 / 25.19。收益在 100K 步最大（约 7.6%），它也是最早、最便宜的检查点，所以锚点是 100K 步。MNIST 或合成 toy 上基线已贴近上限（MNIST 的 FID 2.07 对真实参照 1.56），效应方向在检查点之间翻转，没有辨识力。
